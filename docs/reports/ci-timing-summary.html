Small transition-day sample from October 18–19. Runner-minutes add parallel jobs; wall time measures the wait for results. Billing costs were not measured.

Optimization order

  1. Restrict automatic installers to packaging changes. Keep CI preview executables and manual installers. On the latest ordinary code PR, this removes 19.28 runner-minutes, or 46% of execution. It does not shorten CI's parallel critical path.
  2. Make caches reusable and give keys an intended writer. All six latest native jobs started cold. CI then lost three cache-save races to packaging. A warm rerun finished CI in 3m 51s, but it used a different commit.
  3. Install pinned tools without recompiling them. Audit spends a median 85s installing its tool and 4s auditing. Target 20–35s overall with a verified prebuilt binary. Independently cache cargo-packager.
  4. Run only the affected job groups. Script-only and unrelated workflow changes should not start a native matrix. Preserve a stable required status, all three operating systems, and legacy vault compatibility.
  5. Reuse builds when automatic installers are required. Put packaging after validation in the same platform job. Latest packaging duplicated 14.13 runner-minutes of native tests and release compilation.

Evidence: 739 run records; detailed timings for 443 jobs in 228 runs; 11 native logs. Savings overlap and are not additive. Dependency Review and release contract tests are already inexpensive.
